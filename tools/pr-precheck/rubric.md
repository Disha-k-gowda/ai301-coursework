# Rubric: is this pull request ready to submit?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| plan-fidelity | The branch diff's changed files and behavior read against `plan.md`, including its stated scope, non-goals, and any recorded deviation notes. | Pass when every material change in the diff is within the accepted plan or is covered by an explicit deviation note, and the diff does not silently omit a material part of the plan required to address the issue. An honestly recorded deviation may pass when its changed scope is explicit and still addresses the issue. Fail when the diff silently adds unrelated work, silently drops required planned work, or materially changes the implementation without a recorded deviation. | required |
| description-fidelity | The draft PR title and description in `pr_draft.md` read against the actual branch diff, the issue, and the plan including deviation notes. | Pass when the title and description accurately state what the diff changes, why it changes it, and any material limitation or deviation relevant to review. Fail when the description claims behavior, scope, testing, or plan fidelity that the diff contradicts, or hides a material change or limitation that would mislead a reviewer. | required |
| test-evidence | `test_evidence.md` read against the plan's test plan, the original reproduced behavior or house repro evidence, and the behavior changed by the diff. | Pass when the evidence includes an observable before/after result or equivalent real-code evidence that demonstrates whether the issue-specific behavior changed as intended. An honestly reported failing or unavailable check does not fail this check by itself when the evidence still truthfully establishes the issue-specific outcome and discloses the shortfall. Fail when the evidence is only a claim that testing occurred, lacks an observable result tied to the issue, or cannot distinguish the changed behavior from the original problem. | required |
| repo-checks | `test_evidence.md` read against the repository-required checks named by the PR template and contribution rules, including unit tests, integration tests, lint, and type checking where applicable. | Pass when each required repository check was run and its actual outcome is recorded, including expected outcomes such as an integration command reporting no tests collected. A check may have a non-passing outcome without automatically failing this rubric check when the outcome is honestly recorded and the evidence establishes that it is unrelated to the candidate change or is an expected repository condition. Fail when a required check was not run without a documented repository-supported reason, or when its result is omitted, disguised, or claimed without evidence. | required |
| diff-reviewable | The complete `git diff main...HEAD`, including changed files and hunks, read against the issue and planned scope. | Pass when the diff contains only changes relevant to the issue and accepted plan or recorded deviations, with no generated debris, debug artifacts, accidental edits, unrelated cleanup, or unrelated hunks that obscure the intended change. Fail when unrelated or accidental changes make the candidate change materially harder to review or introduce scope not justified by the package. | required |
| standards-compliant | The draft PR title and description read against `.github/PULL_REQUEST_TEMPLATE.md`, `docs/CONTRIBUTING.md`, relevant issue-thread requirements, and the repo-facts or standards evidence available in the package. | Pass when the draft satisfies the repository's substantive submission requirements, including required template information, truthful testing status, issue linkage, and required AI-use disclosure where applicable. A section may state that something is not applicable when that is truthful. Fail when a required repository ask is omitted, falsely completed, contradicted by the package, or replaced with information that prevents a reviewer from evaluating the submission. | required |

## Verdict rule

Accept only when every required check passes. Any failed or unclear required check makes the verdict reject. Grade a check `unclear` when the available evidence is insufficient to establish that its pass condition is met; `unclear` counts as failure. Preferred checks, if added later, may provide feedback but never change the final verdict. Honest disclosure of a limitation, failed check, or deviation does not by itself require rejection; judge it using the specific pass conditions above and reject only when a required condition is not met.
